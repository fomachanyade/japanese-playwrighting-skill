# japanese-playwright-dialogue — 戯曲ダイアログ実装

プロット(`plot/structure.yaml`)を仕様書、台本を実装とみなし、
フレンチシーン(FS)単位でせりふを書いて整合 lint にかけるスキル。

## 前提ファイル

- `plot/structure.yaml` — japanese-playwright-plot の成果物。**これが無い状態でせりふを書き始めない**(先にプロットスキルへ誘導する)
- `characters/*.yaml` — キャラシート(want / need / first_person / speech_register / ng_words)
- `script/scene-<fs>.md` — 台本。**1ファイル = 1 FS**、frontmatter の `fs:` でプロットと対応付ける

## 台本の記法(templates/scene.md 参照)

1. **せりふ**: `人物名<TAB>せりふ本文`。1発話 = 1行(折り返しはエディタのソフトラップに任せる)
2. **ト書き**: 行頭 `<TAB>` で字下げした行
3. **ト書きブロックとせりふの間は空行1行必須**
4. せりふ内の小さな演技指定は全角括弧()で本文に埋め込む
5. **語り(モノローグ・ナレーション)**: `人物名Ｍ<TAB>語り本文`。語り手は舞台上に居なくてもよい
6. **連名せりふ**: `名A・名B<TAB>本文`(全員が on_stage に必要)
7. **声のみの出演**(電話・放送・留守電): プロット側 `voices:` に宣言すれば on_stage チェックを免除
8. **かぶり(同時発話)**: ★☆▲△をせりふ本文に埋め込む。同じ記号列の対で「相手のせりふのどこから」
   「どのせりふが」かぶるかを示す(★…どうし、☆…どうしが同時)。ペアが揃わないと lint が警告。
   ▲△は同時多発会話(別グループの並行対話)のブロック指定に使う
9. **入れ子相槌**: 長い語りの内部に他者の相槌を `（名前「うん、」）` の形で埋め込める
   (岡田利規式)。語りを切らずに聞き手の存在を書く記法。入れ子話者は舞台上に居ること
10. **沈黙**: ト書き行として `<TAB>間`(平田式の「・・・」行は normalizer が間に変換する)
11. 上記のどれでもない行はフォーマットエラー(全角スペース区切りは warning + タブへの正規化推奨)

## 様式プロファイルと文体計測

文体指標(ターン長・フィラー率・間の記譜密度など)は良し悪しではなく**様式の座標**。
執筆前にどの様式で書くかをユーザーと確認し、書いた後に計測する:

```
python3 scripts/metrics.py script/           # 実測値と各プロファイルのレンジを比較
```

実在戯曲から校正済みのプロファイル(metrics.py 内に定義、コーパスが増えたら更新):
- **自然主義型**: 超短ターン(中央値8〜16字)、フィラー豊富(15〜30%)、間を楽譜のように記譜(0.3〜1.0回/分)
- **明晰会話型**: 口語のリズムから言い淀みを削いだ文体(フィラー3〜10%)、疑問駆動(?終わり25〜40%)、
  間は記譜せず演出に委ねる、語りＭの層を持ちうる
- **ツッコミ駆動型**: 直前の発話行為へのメタ言及(ツッコミ受け16〜28%)が推進力。フィラーは
  自然主義並みに豊富だが間は書かない(テンポは速度で作る)。敬体率が高い(15〜35%)
- **超口語語り型**: 伝聞・引用マーカー11〜18個/1000字(他様式の4〜18倍)。話者は俳優であって
  人物ではなく(代話)、語り(数百字)と相槌(数字)のバイモーダル分布。疑問文がほぼ消える(?終わり0〜8%)。
  「(観客に)」の宛先切替が最小構造単位
- **言葉遊び型**: 音スライド率5〜8%(表層の文字を共有せずに読みの音が隣の発話へ滑る —
  掛詞・同音転換が転換装置として働く)。フィラーほぼゼロ(音まで設計されたせりふに
  言い淀みの余地がない)、語エコーも最大級。※音スライド計測は pykakasi が必要(任意依存)
- **反復喜劇型**: 完全反復率1.2〜2.5%(同一せりふの輪唱・言い直しループが笑いの装置)、
  フィラー最少(3〜8%)、間は書かない。時間層カットバックと併用されることが多い
- **静かな演劇型**: 相槌のみの発話が14〜24%(他様式の3〜5倍)、かぶり記号4〜12/100発話、
  沈黙行が最多(0.8〜1.8回/分)、エコー最少。せりふの過半が読点「、」で終わり、言い切らずに
  次へ流れる/かぶられる前提で書かれる

## 口語せりふの執筆ガイド(コーパスからの原則)

- **感情のピークで発話は短くする**。修飾を増やさない。反復+微変異(「もう無理やろ」→「もう無理や」:
  推量から断定へ一段降りる)が感情の階段になる
- **感情語で説明しない**。感情は物の扱い・話題転換・列挙に転位させる。列挙(駅名、地名)は
  感情の回避行動として機能し、到達しない場所への旅程が感情の器になる
- **説明の職業化**: 世界設定や事実の説明が必要なら、説明することが職業として自然な人物
  (医師・記者・案内人)に集約し、その人物のターン長だけ長くする
- **エコー質問で設定を会話化する**: 聞き返し(「ガイド?」「概念?」)の連鎖は、説明ぜりふを
  書かずに世界を説明する装置。疑問文はドラマの武器にもなる(問いが相手から何かを奪う)
- **発話長の非対称を設計する**: 話者ごとの平均字数の差(聞く側10字/説く側20字)が
  そのまま関係性を可視化する。metrics.py の話者平均字数で確認できる
- **間の記譜は作家変数**: 楽譜のように書き込む流儀と、演出に委ねる流儀がある。
  どちらかに統一し、混在させない
- **会話の推進力は3種類ある**: ①エコー(語の反復で世界を説明する)、②疑問(問いが武器になる)、
  ③ツッコミ(直前の発話行為そのものへの言及)。どれを主駆動にするかが様式を決める
- **敬体は関係の距離計**: 語尾の敬体/常体はキャラ固有ではなく**ペアごと**に設計する。
  関係が変わる瞬間を語尾の変化で見せられる(初対面の敬語が崩れる瞬間、等)
- **予防線の文体**: 否定の連打(「〜とかじゃないです」)で自意識を書く手法。特定キャラの
  固有の声として使い、全員に配らない
- **相槌は第三の層**: せりふ(内容)と間(沈黙)の間に、相槌の層がある。相槌とかぶりは
  上演時間をほぼ消費しない(並行発話)ため、テキスト量の割に上演が短くなる。
  静かな演劇の「速さ」は発話速度ではなく並行度で作られている
- **読点終わりのせりふ**: 「、」で終わるせりふは、言い切らない・相手に続きを渡す・
  かぶられる余白を残す、という三役を兼ねる記譜。乱用せず様式として統一する
- **反復には3つの型がある**: ①エコー(直前の語を引き取って世界を説明する)、
  ②反復+微変異(「もう無理やろ」→「もう無理や」— 感情の階段)、③完全反復の輪唱
  (同一せりふを複数人が回す・言い直す — 笑いの装置)。どの型を主に使うかも様式の一部
- **沈黙のタイトルロール**: 発話量の非対称は「説く側を長く」だけではない。全員を
  均等(平均字数フラット)にした上で主役だけを最短にすると、寡黙さそのものが主題になる
- **音スライドは転換の蝶番**: 掛詞・同音異義は装飾ではなく、場を切らずに世界を移す
  接続装置になりうる(音が同じなら意味は跳べる)。使うなら転換点に集中配備する
- **冗長さと遅さは独立変数**: だらだら話法(伝聞マーカー・言い直しの多さ)は上演を遅くしない。
  実測cpmはむしろ高速圏(379)で、入れ子相槌の並行発話が時間を圧縮する。「余計な言葉」は
  情報ではなくリズムとして時間内に収まる
- **代話の視点管理**: 話者=俳優の様式では、「誰の話を・誰から聞いた体で・誰に向けて」の
  三重の宛先が各発話の設計変数になる。宛先(観客/相手)の切替をト書き(観客に)で明示する
- **決定論の限界を知る**: 音スライド率は言葉遊びの近似にすぎない。漢字分解(人+夢=儚)、
  多言語掛け(九/Q)、意味の二重化は機械では取れない — そこは意味的レビュー(執筆者/Claude)の領域

## 執筆ワークフロー

1. **FSを選ぶ**: 対象FSのカード(on_stage / beat / goal / conflict / outcome / duration_min)と、登場人物のキャラシートを読み込む
2. **文字数予算を確認**: `duration_min × chars_per_minute(既定320)字 ± 20%` が目標。書く前にユーザーと共有する
3. **書く**: 記法に従い `script/scene-<fs>.md` に。キャラシートの speech_register(誰に対してどの口調か)と verbal_tics を反映する
4. **lint を回す**:
   ```
   python3 scripts/lint_script.py plot/structure.yaml script/ --characters characters/
   ```
   error が消えるまで修正。warning は理由をユーザーに説明した上で残す判断も可
5. **意味的レビュー**(lint 通過後、下記の観点で Claude 自身がレビューする)

## lint が検出するもの(scripts/lint_script.py)

| ルール | レベル | 内容 |
|---|---|---|
| fs-ref | error | frontmatter の fs がプロットに存在しない |
| format | error | せりふでもト書きでもない行 |
| blank-line | error | ト書きとせりふの間の空行欠落 |
| speaker | error | プロットの on_stage に居ない人物のせりふ |
| silent | info | 舞台上に居るのに一言も喋らない人物(置き去り検出) |
| long-speech | warning | 400字超のせりふ(プロット側 monologue: true で抑制) |
| char-budget | warning | 文字数が予算 ±20% の範囲外 |
| turn-balance | info | せりふの75%超が一人に偏っている |
| first-person | warning | キャラシートの一人称と異なる一人称の出現 |
| ng-word | warning | キャラシートの ng_words の出現 |

## 意味的レビューの観点(lint では検出できないもの)

- **outcome の達成**: プロットに書いた outcome が、せりふと行動で実際に「起きて」いるか。説明ぜりふで済ませていないか
- **conflict の身体化**: 対立が言い合いだけでなく、行動・沈黙・物(props)の扱いに現れているか
- **サブテキスト**: 人物が本心をそのまま言っていないか。特に secret を持つ人物は、隠しながら漏れるのが原則
- **口調の対人差**: speech_register(相手によって変わる口調)が守られているか。lint は一人称しか見ない
- **beat の温度**: FSの duration_min が長いのに事件が1つしかない、等の密度の問題

## 直しの往復

lint や意味的レビューで**プロット側の欠陥**が見つかることがある(書いてみたら conflict が
成立しない、outcome に無理がある等)。その場合は台本側で辻褄を合わせず、
`structure.yaml` を修正して `lint_plot.py`(japanese-playwright-plot 側)から回し直す。
仕様と実装を一致させたまま進めるのがこのシステムの目的。
