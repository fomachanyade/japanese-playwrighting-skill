# japanese-playwright-plot — 戯曲プロット制作

シド・フィールドの『映画を書くためにあなたがしなくてはならないこと(Screenplay)』のパラダイムを、
上演時間 60 分程度・場転の少ない舞台劇に写像してプロットを設計するスキル。

## 前提となるモデル

- **単位はフレンチシーン(FS)**: 登場人物の出入りがあるたびに区切る。カード 1 枚 = FS 1 個、全体で 8〜12 枚が目安
- **景(act)は物理的な舞台転換の単位**: 1〜3 景が基本。4 以上で警告、10 以上はエラー
- **時間予算**: 1 分 ≒ 320 字。FS ごとに `duration_min` を割り当て、合計を 55〜60 分に収める
- **パラダイム(60分の場合)**: 第一幕 0–15 分 / PP1 は 12–17 分 / ミッドポイント 27–33 分 / PP2 は 40–47 分 / クライマックス 48–58 分。`target_minutes` を変えれば比率で自動スケールする

## ワークフロー(この順番を守る。lint が順番違反を検出する)

ファイル構成は `plot/structure.yaml`(骨格+全FSカード)と `characters/名前.yaml`(キャラシート)。
スキーマは `schema/structure.yaml` と `schema/character.yaml` を読むこと(コメントで全フィールドを説明済み)。

1. **クライマックスを決める** — 物語がどこへ向かうかを最初に確定する。`paradigm.climax` に summary を書き `decided: true`
2. **オープニングを決める** — クライマックスと「対」になる開始点。エンディングが分かればオープニングは導かれる
3. **PP1 / PP2 を決める** — 第一幕・第二幕の終わりで物語を別方向へ「回転」させる事件。**PP1 は一撃の事件でなくてもよい**: 静かな自然主義では「別の世界への越境が完了する地点」(主人公が新しい場に入り、その世界の全員が揃う等)が PP1 として機能する。この場合も累積時間の目安は同じ
4. **ミッドポイントを決める** — 第二幕の中間点。偽りの勝利/敗北が置かれることが多い
5. **カードを書く** — `templates/card.yaml` を雛形に、残りの FS を埋める。骨格点を含む FS は goal / conflict / outcome 必須、他は beat 1 行でも良い
6. **lint を回す** — `python3 scripts/lint_plot.py plot/structure.yaml`。error が消えるまで修正
7. **意味的レビュー**(lint 通過後、下記の観点で Claude 自身がレビューする)

ユーザーとの壁打ちでは、一度に全部埋めようとせず、上の順番で 1 ステップずつ質問しながら進めること。
クライマックスが決まっていないのにシーンの話を始めたら、一旦止めてクライマックスに戻す。

## lint が検出するもの(scripts/lint_plot.py)

| ルール | レベル | 内容 |
|---|---|---|
| field-order | error/warning | climax 未確定でカード作成 / 骨格4点未確定でカード5枚以上 |
| act-count | error/warning | 景 10 以上 / 4 以上 |
| act-transition | info | 同一場所の連続する景(暗転で済むかも) |
| fs-count | info | FS が 8〜12 の範囲外 |
| stage-ledger | error | 出入り簿の検算不一致(前FS + enters − exits ≠ on_stage) |
| fs-boundary | error | enters/exits 両方空のFS境界(time_jump なし) |
| backbone-detail | error | 骨格FSに goal/conflict/outcome 欠落 |
| duration-total | warning | 合計が target−5 〜 target 分の範囲外 |
| paradigm-timing | warning | PP1/ミッドポイント/PP2/クライマックスの累積時間が目安外 |
| chekhov | error/warning | setup と payoff の不対応(チェーホフの銃) |
| relationship-static | info | 全編で人物の組み合わせが変化しない登場人物 |

## 意味的レビューの観点(lint では検出できないもの)

lint がクリーンになったら、以下を自分でチェックしてユーザーに報告する:

- **問いと答えの対、または対句**: オープニングで提示される劇的な問い(dramatic question)に、クライマックスが回答しているか。対応は Q&A 型だけでなく **rhyme(対句)型** — 冒頭と終盤が同じモチーフの変奏で韻を踏む形 — でもよい(例: 現実の道行で開き、想像の道行で閉じる)
- **アンチクライマックスの許容**: クライマックスは「達成」でなくてよい。対峙の失敗・和解の不発(チェーホフ型)もクライマックスとして機能する。位置と機能(問いに決着がつく)が満たされていれば良く、決着の内容が「回答の不可能性の上演」であっても構わない。ただしその場合、**失敗を観客が回答として受け取れる準備**(反復されてきたモチーフ、到達しない場所への言及など)が積まれているかを確認する
- **want と need**: 主人公の want(自覚的欲求)と need(無自覚の必要)がキャラシートにあり、クライマックスがどちらをどう扱うか明確か
- **各FSの必然性**: そのFSを削ったら物語が壊れるか。壊れないFSは削るか他と統合する候補
- **conflict の実在**: goal はあるが conflict が「気まずい」程度で具体的な対立になっていないFSはないか
- **outcome の連鎖**: 各FSの outcome が次のFSの前提になっているか(「そして」ではなく「だから/しかし」で繋がるか)

## 拡張要素(様式によって使う)

- **語り(Ｍ)**: モノローグ・ナレーションの層。時間圧縮と内面開示を担い、場転の多い構成を支える。
  ダイアログ側の記法は `人物名Ｍ<TAB>語り`
- **回想**: FSに `flashback: true`。出入り台帳の連続性チェックから除外される
- **声のみの出演**: `voices:` に宣言(キャスター、留守電、電話の相手など)
- **常設多重セット(ゾーン切替型)**: 複数の場所を舞台上に同時に建て込み、照明で切り替える構成。
  `stage_zones:` に宣言すると景の数の制約がゾーン数に切り替わり、場の切替は無制限になる。
  切替コストゼロを活かした「柱の場(20分級)と句読点の場(1分未満)」のリズム設計が可能になる
- **開場の演出(preshow)**: 開演前、客入れ中から舞台上の生活を始める手法(平田オリザ式)。
  景に `preshow: true` を付けると本編の時間予算・パラダイム位置の計算から除外される
- **FS密度の経験則**: 自然主義系の完成台本を逆生成すると、物理FSは平均2〜3分/個に収束する
  (『おかえり』1.8分、『眠れない夜』約2.6分)。平田オリザは台本自体を「幕・場・出入り」の
  三層番号(1・1・2 など)で刻んでおり、出入りを単位とするこのスキーマの実在検証になっている
- **時間層カットバック(time_layer)**: 同一の場所を「現在/過去」の時制で交互に切り替える構造
  (映像編集の文法)。景の location にゾーン、`time_layer:` に時制を分離して書く。
  切替コストは照明のみでゼロに近く、切替回数に制約はない
- **兼ね役(casting)**: 少人数座組で多役を演じる場合、`casting: {俳優名: [役名, ...]}` を宣言
  すると台本側の話者に俳優名を使える(役名/俳優名の二重層)
- **変容型(シームレス転換)**: 景を一切切らず(見出しゼロ)、言葉の音スライドと役の変容で
  世界を移す構造(野田秀樹型)。現実層と神話層が同一空間・同一俳優に重なる。
  この様式では景/FSの台帳よりも「どの音・どの語が世界間の蝶番か」の設計が構造の本体になる
- **代話型(語りリレー)**: 話者が人物ではなく俳優(男優1、女優2…)で、人物は語られる対象として
  だけ存在する構造(岡田利規型)。出入り台帳は無意味化し、分割単位は「語り手の交代」と
  「宛先の切替(観客宛て/相手宛て)」になる。景(場)は語りのまとまりとして残る
- **記法規約は作家ごとに違う**: 入場/退場の記譜がない台本もある(scripts/extract_plot.py の
  出入りヒューリスティックは記譜のある台本にのみ有効)。既存台本を取り込むときは、
  まずその台本の規約(出入り・間・語りをどう書くか)を観察してから道具を選ぶ
